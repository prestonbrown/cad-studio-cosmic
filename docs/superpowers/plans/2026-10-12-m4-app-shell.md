# M4 App Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The libcosmic application shell around the finished engine and viewer — welcome + project windows, resizable chat/3D/schematic panes, the full chat transcript UI driven by engine events, schematic display, sheets, and the spec's M4 vertical slice: prompt → agent → outputs appear → model renders.

**Architecture:** One `cosmic::Application`, multi-window (Welcome + one window per project), panes via `cosmic::widget::PaneGrid`. All decision logic lives in PURE, GUI-free modules inside the app crate (`chat`, `panes`, `camera_input`, `mesh_stats`, `schematic` math, `recents`) so every behavior is testable without opening a window; widget code is a thin mapping layer. The engine side of the port already exists from M1/M2: `engine::project::store::{ChatMessage, ToolActivity, validate_project_name, save_chat, load_chat}`, `engine::project::layout::{PaneKind, Axis, LayoutNode}`, `engine::settings::Settings`, `engine::watch::watch_directory`, `engine::agent::session::{Session, TurnHandle, EngineEvent, TurnOutcome}`. The shell wires them; it does not re-port them.

**Tech Stack:** libcosmic 1.0.0 (git rev `dbc62f2`, feature `wgpu`), cosmic-config (same git rev), iced via libcosmic only, pulldown-cmark (spec §4.4), tokio via cosmic's default executor.

**Spec:** docs/superpowers/specs/2026-10-11-cad-studio-cosmic-port-design.md (§4.4 app crate, §10 M4, §6 platform mapping, §7 testing strategy). Carry-forwards: docs/research/carry-forwards.md M4 section (binding). Research: docs/research/libcosmic-landscape.md. Upstream fidelity sources (vendored 2026-10-12 at upstream `ed2ccaf`): fixtures/upstream-source/{App,Chat,Project,Schematic,Shared,Agent}/*.swift — every behavior constant in this plan is transcribed from them; when this plan and a Swift file disagree, the Swift file wins and the discrepancy goes to the controller.

## Global Constraints

- Engine stays GUI-free (spec §4.2). App adds `engine = { path = "../engine" }` and `viewer = { path = "../viewer" }`; viewer types stay behind the adapter module.
- libcosmic pinned at git rev `dbc62f2d899cdbfbe43d170689ddc0290db663f4` with feature `wgpu`; `cosmic-config` added as a workspace dependency pinned to the SAME rev (libcosmic workspace crate). NEVER a pop-os/iced.git dependency.
- wgpu 28 exact (the fork's pin) — already in the workspace.
- User-visible strings go through `fl!()`/`cosmic::locale` with keys from app/i18n/en/main.ftl (336 keys extracted at M0). Missing key → add to en/main.ftl with upstream's English value, U+2019 apostrophes where upstream uses them. No hardcoded English in views.
- All new logic modules are pure (no cosmic/iced types) and unit-tested; widget files contain mapping only. Fake-agent fixtures (fixtures/fake-agent/) drive every agent-path test — no network, no real CLI.
- thelio gates are controller-owned, single-invocation, never stacked. Local (macOS/Metal) gates iterate; thelio validates at merge.
- Conventional commits; stage explicit paths only; never `git add -A`/`-u`; never `git rm`.
- Tests fail if the feature is removed (no vacuous asserts); timing tests use bounded poll loops, never fixed sleeps.

## Review Focus

Five failure modes the spec implies but task tests might not exercise — each pinned in the owning task:

1. **Drain-stall freezes cancel** — the event channel backpressures at 256 deep; cancel is only polled between translations (carry-forwards, T7/T8 forensics). A flooded event stream must never make cancel unresponsive. → Task 3 flood test.
2. **Auth 401 false-positive** — `"401"` substring-matches token counts/durations in error text (e.g. "1401 tokens"); wrong auth classification shows the open-terminal action on ordinary failures. → Task 1 word-boundary test.
3. **chat.json absent or corrupt on open** — upstream tolerates (`try? … ?? []`); the app must open with an empty transcript, not crash, and rewrite a valid file on next save. → Task 1 load test.
4. **Turn ends without TurnFinished** (bridge task dies / channel closes first) — a tool row left `running` forever and a queue stuck mid-state. → Task 3 channel-close test + Task 1 fail-open rule.
5. **Window resize re-layout loses pane state** — LayoutNode persistence must round-trip through real resize/drag/split sequences, not just serde. → Task 4 mutation round-trip test.

### Task 1: Chat transcript reducer (pure)

**Files:**
- Create: `app/src/chat.rs` (+ in-crate `#[cfg(test)]` mod), `app/tests/chat_replay.rs`
- Modify: `app/src/main.rs` → `app/src/lib.rs` split (lib holds modules + tests; bin stays thin), `app/Cargo.toml` (engine path dep, tokio dev-dep for replay tests)

**Interfaces:**
- Consumes: `engine::agent::session::{EngineEvent, TurnOutcome}`; `engine::project::store::{ChatMessage, ToolActivity, save_chat, load_chat}` (upstream-parity shapes: `ChatMessage { id: Uuid, role, text, tool: Option<ToolActivity> }` — read store.rs:40-100 for the exact fields; the reducer never invents fields).
- Produces (upstream ChatViewModel.swift names, adapted): 
  - `ChatState { messages: Vec<ChatMessage>, active_thinking: bool, last_text_id: Option<Uuid>, unconfirmed: Vec<Uuid> }`
  - `ChatState::new(persisted: Vec<ChatMessage>) -> Self` (empty on load error)
  - `ChatState::apply(&mut self, event: &EngineEvent)` — the full translation:
    - `Started` → no row
    - `Thinking { .. }` → sets `active_thinking = true` only if no streaming row is open (upstream shows a thinking indicator via `activeThinkingID`); NEVER appends a message (engine emits thinking only as usage counts — carry-forwards M4)
    - `TextStreaming { text }` → append to the FIRST unconfirmed row, FIFO (create it if none; push id to `unconfirmed`) — upstream `appendText` + `unconfirmedTextIDs.removeFirst()` on confirm
    - `TextConfirmed { text }` → `setText` on the first unconfirmed row and pop it from `unconfirmed`; if `unconfirmed` is empty, append a confirmed row
    - `ToolStarted { id, title }` → append message with `tool: Some(ToolActivity { tool_use_id: id, state: running, input: String::new(), preview: None, output: None })`, text = title
    - `ToolInput { id, partial }` → `update_tool`: append partial to `tool.input`; refresh `preview` per the throttle rule
    - `ToolFinished { id, output, is_error }` → `complete_tool`: state = failed/succeeded, output set, preview cleared
    - `System { text }` → append `role: system` message
    - `TurnFinished(Success)` → `fail_running_tools()` (running → failed, preview cleared — upstream `failRunningTools`), thinking cleared
    - `TurnFinished(Failed { auth: true, .. })` → fail-open tools + append system row carrying `needs_terminal: true` (the row-level flag the view maps to the open-terminal action; carry-forwards M4)
    - `TurnFinished(Failed/CANCELLED/..)` → fail-open tools + thinking cleared
  - `ChatState::should_emit_preview(&self, last_emit: Instant, now: Instant) -> bool` — `now - last_emit >= 150ms` (upstream 0.15 s throttle; the ENGINE forwards every delta, the APP throttles display — carry-forwards M4)
  - `ChatState::fail_running_tools()`, `can_send()`, `take_draft()` (trim; empty text + no attachments → None) — port ChatViewModel.swift verbatim
  - `auth_flag(details: &str) -> bool` — engine's `is_authentication_error` OR the word-boundary 401 check: `api error status 401` token match (regex `\b401\b` against the details string; plain-substring `"401"` is the upstream bug — carry-forwards M4)

**Tests (write first, RED):**
- `text_streaming_reconciles_fifo` — two `TextStreaming` then one `TextConfirmed`: first row replaced, second still unconfirmed (port the upstream ordering).
- `tool_lifecycle_full` — Started/Input×3/Finished(ok) → one row, input concatenated, preview cleared, state succeeded; error path sets failed.
- `fail_open_at_turn_end` — ToolStarted without Finished + `TurnFinished(Success)` → row failed.
- `auth_word_boundary` — `"api error status 401"` → true; `"1401 tokens used"` → false; `"duration 4.401s"` → false.
- `corrupt_chat_json_opens_empty` — `ChatState::new(load path that is invalid JSON)` → empty, no panic.
- `thinking_never_appends` — Thinking event → message count unchanged.
- Replay integration (`app/tests/chat_replay.rs`): run `engine::agent::session::Session` with the fake agent (`fixtures/fake-agent/fake_claude.py`, scenarios from fixtures/fake-agent/scenarios/) in a temp project; collect events; drive `ChatState`; assert the final transcript (row count, roles, tool states, persisted file via `save_chat` round-trips `load_chat`).

**Steps:** lib/bin split + deps → tests → RED → implement → GREEN locally (`cargo test -p app`) → commit `feat(app): chat transcript reducer — engine events to persisted rows`.

### Task 3: Engine bridge (turn driving, queue, drain)

**Files:**
- Create: `app/src/bridge.rs`, `app/tests/bridge_e2e.rs`

**Interfaces:**
- Consumes: Task 1's `ChatState`; `Session::send/run_turn`, `TurnHandle { events, cancel, pid }`.
- Produces:
  - `Bridge::new(settings, project_root) -> (Bridge, cosmic::Task<Message>)` — owns the `Session`; the Task is a `cosmic::task::stream` draining `TurnHandle::events`, forwarding one `Message::Engine(EngineEvent)` per event; **cancel is polled between event translations** (drain with `try_recv` + `poll_cancel` select; a stalled translation never wedges cancel — Review Focus 1).
  - Queue semantics (upstream ChatInputView/ChatView): sends while a turn runs are queued (FIFO); after `TurnFinished(Success)` the next queued prompt auto-runs after **1.0 s**; after any failure the queue PAUSES (banner + manual resume); cancel clears the running turn only.
  - `Bridge::cancel()`, `Bridge::enqueue(text)`, `Bridge::resume_queue()`.
  - Turn end → `save_chat` to the project store; `Shutdown`/drop → cancel + engine reap.

**Tests (fake-agent e2e):** `send_success_streams_and_saves`; `auth_failure_pauses_queue` (scenario emitting 401 → queue paused, no auto-run); `cancel_mid_turn_fails_open` (#exit directive); `flood_does_not_wedge_cancel` — fake agent emits ~5k events while the consumer translates slowly; cancel lands within a bounded poll window (assert elapsed < bound); `channel_close_without_turn_finished` — drop the receiver mid-turn → bridge marks the turn failed and fails open tool rows (Review Focus 4).

**Steps:** tests → RED → implement → GREEN → commit `feat(app): engine bridge — drain loop, cancel-between-events, send queue`.
