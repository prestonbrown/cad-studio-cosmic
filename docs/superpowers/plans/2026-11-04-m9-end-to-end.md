# M9 End-to-End Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the port against the spec's success criteria with a real agent, close or rule every open carry-forward, and ship user-facing docs.

**Architecture:** The real-agent run is scripted through the existing CAD_STUDIO_DRIVE harness (app/src/drive.rs) plus a few new commands, captured with scripts/rig/capall.sh, and asserted from the project folder on disk. Polish items each land as a small test-first change in the module that owns them, on the shared `app/src/ui/` kit. Docs are README plus one architecture page.

**Tech Stack:** Rust workspace (engine/viewer/app), libcosmic pin dbc62f2, Fluent catalogs (`fl!`), build123d venv, the cad-dev rig (incus LXC on zeus; Xvfb + GL/llvmpipe), thelio when reachable.

**Spec:** `docs/superpowers/specs/2026-10-11-cad-studio-cosmic-port-design.md` §1 (success criteria 1-4), §7 testing ("Real-agent smoke"), §10 M9. Open items: `docs/research/carry-forwards.md` (§M9 / general, plus M8-section entries naming M9).

## Global Constraints

- No builds or test suites on mercury. Builds, tests and captures run on the rig (`scripts/rig/rig.sh`, see `scripts/rig/README.md`) or thelio; commits only on mercury or thelio.
- One fresh-target `cargo test --workspace` + `cargo fmt --all --check` + `cargo build --release -p app` (0 warnings) gate per batch, run by the controller, never per task.
- COSMIC preferences win: accent, font family, light/dark, corner radii and text scale come from the theme. Parity covers structure, layout, element presence, icons and semantic colors (measured, never eyeballed).
- View code uses `app/src/ui/` components and `crate::typography`; extend a component, never fork a twin.
- Every user-visible string goes through `fl!` with entries in all four catalogs (en active; it/de/fr present).
- Static menu roots and static item labels until Task 5 rules otherwise (`docs/research/libcosmic-menu-dynamic-items-bug.md`).
- No new workspace dependency without a ruling written into this plan.
- Comments state present-tense facts; no history, task ids or review narration. Stage explicit paths; plain `-m` messages; no attribution.
- Never file bug reports with pop-os/libcosmic.
- Protect Preston's real state: never touch `~/Downloads/Keyer Box`, his CAD Studio defaults or his venv on mercury.
